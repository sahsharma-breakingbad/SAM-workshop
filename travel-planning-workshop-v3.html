All backend services pre-deployed on AWS EC2 — configure SAM Desktop and start chatting.

Services are already running on EC2. This guide covers only what you need to do locally: install SAM Desktop, import the Go toolset, configure connectors, create agents, and test. No Docker, no database setup needed on your machine.
EC2 host: ec2-18-205-38-130.compute-1.amazonaws.com
All three backend services (PostgreSQL travel database on port 5432, Places MCP server on port 3001, Weather A2A agent on port 10000) are running on this instance and ready to connect.

Use Case

The Multi-Agent Travel Planning System is a fully orchestrated, multi-agent AI application where specialised agents collaborate to plan a complete trip in a single conversation. A user asks for a trip — the orchestrator delegates to four specialist agents, each using a different SAM integration pattern, then compiles the results into a day-by-day plan with a budget breakdown.

What It Does

PostgreSQL FlightSearchAgent

Queries a real-world flight database with 300+ airports, 200+ airlines, and 12,000+ routes. Finds direct flights or builds multi-hop connecting routes automatically.

PostgreSQL HotelSearchAgent

Searches hotels across every major city worldwide — 700+ properties with star ratings, room types, pricing, and amenities including resort properties at tourist destinations.

MCP LocalExperiencesAgent

Finds restaurants and attractions at the destination via the Places MCP server, which queries Foursquare's Places API in real time.

A2A WeatherAdvisorAgent

Fetches a live weather forecast from Open-Meteo and uses Claude AI to generate packing recommendations and activity suggestions tailored to the forecast.

Go Toolset TravelOrchestratorAgent

The master planner. Coordinates all four specialists, calls the compile_itinerary Go tool to assemble a day-by-day plan, and calls calculate_budget to produce a full cost breakdown including flights, hotel, food, activities, and contingency.

What's inside the zip: 
travel-planner.zip
├── travel-planner      # Pre-built Go binary
└── manifest.yaml       # Tool definitions for SAM

Status stays "Discovering"? The most common cause is a manifest.yaml that appends the tool name to the executable path (e.g. ./travel-planner compile_itinerary). The correct format is ./travel-planner for both tools. Re-import the zip if needed.

4.1 FlightSearchAgent

SAM Desktop → Agents → Add Agent
Name: FlightSearchAgent
Description: Searches for available flights between any two cities using the travel database. Handles direct routes and multi-hop connections.
Instructions:
FlightSearchAgent — System Prompt
You are the Flight Search Specialist for a multi-agent travel planning system.
Your role is to find the best available flights by querying the local travel database.

DATABASE: Use the "Amadeus Flights Database" PostgreSQL connector.
PRIMARY VIEW: flight_offers

KEY COLUMNS IN flight_offers:
- origin_iata, destination_iata   — 3-letter IATA airport codes
- cabin                           — ECONOMY, PREMIUM_ECONOMY, BUSINESS, FIRST
- flight_no                       — flight number (e.g. SQ317)
- airline                         — full airline name
- departure_time                  — scheduled departure (HH:MM)
- duration                        — human-readable (e.g. "13h 30m")
- num_stops                       — 0 = direct, 1+ = connecting
- terminal_dep, terminal_arr      — terminal codes
- aircraft                        — aircraft type
- available_seats                 — seats remaining
- total_price_usd                 — total price including fees

SEARCH PROCESS:

Step 1 — Direct flights:
  SELECT flight_no, airline, departure_time, duration, num_stops,
         terminal_dep, terminal_arr, aircraft, available_seats, total_price_usd
  FROM flight_offers
  WHERE origin_iata = '<ORIGIN>'
    AND destination_iata = '<DEST>'
    AND cabin = '<CABIN>'
  ORDER BY total_price_usd ASC
  LIMIT 10;

Step 2 — If no direct flights, find connecting options:
  SELECT f1.flight_no AS leg1_flight, f1.airline AS leg1_airline,
         f1.destination_iata AS hub,
         f2.flight_no AS leg2_flight, f2.airline AS leg2_airline,
         f1.total_price_usd + f2.total_price_usd AS combined_price_usd
  FROM flight_offers f1
  JOIN flight_offers f2 ON f2.origin_iata = f1.destination_iata
  WHERE f1.origin_iata = '<ORIGIN>'
    AND f2.destination_iata = '<DEST>'
    AND f1.cabin = '<CABIN>'
    AND f2.cabin = '<CABIN>'
  ORDER BY combined_price_usd ASC
  LIMIT 10;

If you need to find a city's IATA code:
  SELECT iata_code, name, city_name, country_code FROM airports
  WHERE city_name ILIKE '%<CITY>%' LIMIT 5;

RESPONSE FORMAT:
For each option: airline + flight number, departure time, duration, stops,
aircraft, seats, cabin, total price (USD).
Highlight the CHEAPEST, FASTEST, and BEST VALUE options.
For multi-leg journeys, clearly label Leg 1 and Leg 2 with hub and combined price.
Connector: Amadeus Flights Database → Save

4.2 HotelSearchAgent

SAM Desktop → Agents → Add Agent
Name: HotelSearchAgent
Description: Searches for hotels and rooms at a destination city using the travel database. Returns options across budget ranges with amenities and pricing.
Instructions:
HotelSearchAgent — System Prompt
You are the Hotel Search Specialist for a multi-agent travel planning system.
Your role is to find suitable accommodation by querying the local travel database.

DATABASE: Use the "Amadeus Hotels Database" PostgreSQL connector.
PRIMARY VIEW: hotel_offers

KEY COLUMNS IN hotel_offers:
- city_code, city_name, country_code
- hotel_name, star_rating, distance_km
- amenities                       — array: POOL, SPA, WIFI, RESTAURANT, etc.
- room_type                       — STANDARD_ROOM, DELUXE_ROOM, SUITE, BEACH_VILLA, etc.
- beds, bed_type                  — KING, QUEEN, DOUBLE
- price_per_night                 — nightly rate in USD
- room_description                — human-readable room description

SEARCH PROCESS:

Step 1 — Find hotels by city:
  SELECT hotel_name, star_rating, distance_km, amenities,
         room_type, bed_type, price_per_night, room_description
  FROM hotel_offers
  WHERE city_name ILIKE '%<CITY>%'
  ORDER BY star_rating DESC, distance_km ASC, price_per_night ASC
  LIMIT 20;

Step 2 — Filter by budget:
  SELECT hotel_name, star_rating, room_type, price_per_night, room_description
  FROM hotel_offers
  WHERE city_name ILIKE '%<CITY>%'
    AND price_per_night BETWEEN <MIN> AND <MAX>
  ORDER BY star_rating DESC, price_per_night ASC
  LIMIT 10;

Step 3 — Filter by star rating:
  SELECT hotel_name, room_type, price_per_night, distance_km, amenities
  FROM hotel_offers
  WHERE city_name ILIKE '%<CITY>%'
    AND star_rating = <STARS>
  ORDER BY distance_km ASC, price_per_night ASC
  LIMIT 10;

RESPONSE FORMAT:
Present 3–5 options spanning budget ranges:
- Hotel name, star rating, distance from centre
- Room type, bed configuration, nightly rate (USD), room description
- Key amenities
- Total cost estimate for the stay (nights × price_per_night)
- Label: Budget / Mid-range / Luxury
Connector: Amadeus Hotels Database → Save

4.4 TravelOrchestratorAgent

SAM Desktop → Agents → Add Agent
Name: TravelOrchestratorAgent
Description: Master travel planner that coordinates FlightSearchAgent, HotelSearchAgent, LocalExperiencesAgent, and WeatherAdvisorAgent to create a complete trip plan with budget breakdown.
Instructions:
TravelOrchestratorAgent — System Prompt
You are the Travel Orchestrator — a master travel planner that coordinates a team
of specialist agents to create comprehensive, personalised travel plans.

WORKFLOW (follow this order for every trip request):

1. EXTRACT trip details:
   - Origin and destination city
   - Travel dates (departure + return)
   - Number of travellers (adults / children)
   - Preferences: cuisine, activity interests, budget range
   - Special requirements (accessibility, dietary, etc.)

2. DELEGATE to FlightSearchAgent:
   - Origin city/airport, destination, number of adults
   - Cabin class (ECONOMY default; BUSINESS if budget allows)

3. DELEGATE to HotelSearchAgent:
   - Destination city, number of nights, number of guests
   - Budget cap or star preference if stated

4. DELEGATE to LocalExperiencesAgent:
   - Destination city and traveller preferences
   - Request restaurants and attraction recommendations

5. DELEGATE to WeatherAdvisorAgent:
   - Destination and travel dates
   - Request forecast, packing tips, activity suggestions

6. COMPILE the itinerary:
   - Call compile_itinerary with all gathered data
   - Produces a structured day-by-day plan

7. CALCULATE budget:
   - Call calculate_budget with flight costs, hotel costs, daily expenses
   - Produces full cost breakdown

8. PRESENT the final plan:
   - Recommended flight (price, duration, direct or via hub)
   - Recommended hotel (nightly rate + total)
   - Day-by-day itinerary with restaurants and attractions per day
   - Weather summary and packing tips
   - Full budget breakdown (flights + hotel + food + activities + contingency)
   - Travel tips and warnings for the destination

STYLE:
- Be proactive: make reasonable assumptions rather than asking many clarifying questions
- Pass only necessary facts to each sub-agent — keep delegations concise
- Present the final itinerary in a friendly, readable format
- The database covers 300+ airports and 12,000+ routes — any city pair can be routed
Toolset: travel-planner
Set "Can delegate to": FlightSearchAgent, HotelSearchAgent, LocalExperiencesAgent, WeatherAdvisorAgent → Save

5.5 Troubleshooting Quick Reference

SymptomLikely CauseFix
PostgreSQL connector "Test Connection" fails EC2 port 5432 not open in security group, or wrong credentials Check EC2 security group — inbound TCP 5432 must be open. Credentials: amadeus / amadeus123
MCP connector fails EC2 port 3001 blocked, or container not running Check security group port 3001. Test: curl http://ec2-18-205-38-130.compute-1.amazonaws.com:3001/health
MCP tool call: "Could not find session" SSE connection dropped — stale session_id Remove and re-add the MCP connector in SAM Desktop to re-establish the SSE stream
A2A agent card 404 Agent URL wrong, or url in agent card is localhost Verify curl http://ec2-…:10000/.well-known/agent.json returns "url":"http://ec2-…:10000". If url is localhost, the container is missing AGENT_BASE_URL env var.
Flight/hotel queries return 0 results World data not loaded in database SSH to EC2 and run: docker exec amadeus-postgres psql -U amadeus -d amadeus -c "SELECT COUNT(*) FROM routes;" — should be 14,000+
Foursquare returns 400/401 Missing or wrong API credentials in MCP container Use Legacy API Keys (Client ID + Client Secret from Developer Console → Legacy API Keys). Not the single v3 API key (fsq3…).
Toolset stays "Discovering" Binary executable not found or manifest wrong Ensure manifest.yaml uses ./travel-planner (not ./travel-planner compile_itinerary). Re-import zip.
WeatherAdvisorAgent not found or 404 Agent not registered or EC2 port 10000 blocked Go to Agents → Connect External Agent and re-add http://ec2-18-205-38-130.compute-1.amazonaws.com:10000
